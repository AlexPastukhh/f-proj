# Portable Projection — localhost integration (P3 D-065)

**Prototype status:** source/installed tests apply to a separate internal
0.1.0 candidate; this is not a public release or accepted browser UX.

## One Projection, two views

After a **trusted, non-blocking** `Feature Projection: Refresh`, the
extension builds one in-memory JSON-compatible semantic snapshot from
the analyzed frontend/backend Situations. It renders:

- Markdown, as before, in the VS Code Projection editor (with CodeLens
  and native Test Explorer navigation).
- A complete offline `projection.html` with the same Situations,
  expected behaviors, literal assertions, unmatched parts and
  `vscode://file/…:line:column` source links.

No public JSON export, automatic network upload, localhost server,
HTML JavaScript or additional semantic analysis is involved.
## Serve from your existing localhost app

In workspace `.vscode/settings.json`, optionally set:

```json
{
  "featureProjection.portableHtmlDirectory": "C:\\Projects\\my-local-app\\public\\feature-projection"
}
```

The directory **must be an absolute path**. The extension writes only
`projection.html` there, after a successful trusted Refresh. For a
typical static-assets app the file becomes available at something like
`http://127.0.0.1:3000/feature-projection/projection.html`; your app
may also embed it in an `iframe` pointing to that local URL.

The server, route, port and reload behavior belong to **your app**:
Feature Projection does not start a server or implement hot reload.
The HTML is an offline snapshot; refreshing the browser is needed
to see newly written content. Clicking source links may prompt
the browser for permission to open VS Code, and some browsers or
security policies may block external editor links.
## No setup required for local-only use

With no `portableHtmlDirectory`, a stable workspace-qualified
`projection.html` is written below VS Code's **extension global
storage**, not into project source. Its path is logged to the
**Feature Projection** output channel after Refresh.

Run **Feature Projection: Open HTML Projection** to open the last
fresh document using the operating-system default handler; the command
does not regenerate the Projection. It refuses opening while the
workspace is untrusted or the Projection is Stale/Error.

## Safety and freshness

- HTML contains **literal test assertions and user-authored names**.
  Do **not** make its serving route publicly reachable or publish the
  generated file without your own content review. Keep the localhost
  server bound to loopback unless you deliberately add authentication.
- The writer uses a temporary file and replaces `projection.html`
  atomically. It **refuses** an existing `projection.html` that was
  not generated by Feature Projection, to avoid overwriting user files.
- Restricted Mode, blocking diagnostics, and source changes detected
  during Refresh cannot replace the last complete HTML snapshot.
- If the explicitly configured localhost directory is inside a
  watched project, only the generated HTML and its atomic temp file
  are excluded from source watchers. Other source changes still
  mark the Projection Stale.
- When source changes after a good Refresh, the old HTML remains
  on disk and is potentially stale until Refresh succeeds again.
  This is **not** live synchronization.
- Existing VS Code Markdown, Test Explorer, registered C# Usages and
  the exclusion of user-visible Rename Preview remain unchanged.
- Manual browser/localhost integration acceptance remains **PENDING**;
  source tests and isolated installed Extension Host smoke are
  technical evidence only.
